# /audit-brain

Пройтись по `.claude/shared/*.md` и корневому `CLAUDE.md`, проверить размеры, предложить рефактор при превышении лимитов.

## Шаги

1. Прочитай все файлы в `.claude/shared/` и корневой `CLAUDE.md`. Для каждого посчитай строки.
2. Сопоставь с лимитами:
   * `current-state.md` — ≤ 50 строк
   * `architecture.md`, `conventions.md`, `glossary.md` — ≤ 200 строк каждый
   * корневой `CLAUDE.md` — ≤ 100 строк
3. Для каждого файла сверх лимита:
   * Выдели части, которые **не нужны каждой сессии** (история, обоснования, альтернативы, детали редкого использования).
   * Предложи: что вынести в whitepaper (`leaf-docs`) как public-safe решение, что удалить как неактуальное.
   * Покажи предполагаемый размер после рефактора.
4. По подтверждению пользователя:
   * Синкни нужное в `leaf-docs` через `/sync-docs` или напрямую.
   * Убери блок из shared-файла, при необходимости оставь короткую ссылку на whitepaper.

## Ориентиры при ревизии

* Устоявшееся архитектурное решение → кандидат в `leaf-docs/docs/03-architecture/` (public-safe формулировка)
* Продуктовый принцип → `leaf-docs/docs/01-vision/philosophy.md`
* Устаревшая деталь → удалить
* Implementation moat (SQL, пороги, bytes layouts) → приватный модуль кода, НЕ в shared и НЕ в whitepaper

## Когда запускать

* Раз в ~квартал — плановый аудит
* Триггерно — когда файл перевалил за лимит

## Чего НЕ делать

* Не удалять информацию, которая не переехала в whitepaper. Сначала перенос — потом удаление.
* Не публиковать implementation-детали в whitepaper (это публичный репо).
