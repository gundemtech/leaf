# /audit-brain

Пройтись по `.claude/shared/*.md` и корневому `CLAUDE.md`, проверить размеры, предложить рефактор при превышении лимитов (ADR-004).

## Шаги

1. Прочитай все файлы в `.claude/shared/` и корневой `CLAUDE.md`. Для каждого посчитай строки и символы.
2. Сопоставь с лимитами:
   * `current-state.md` — ≤ 50 строк
   * `architecture.md`, `conventions.md`, `glossary.md` — ≤ 200 строк каждый
   * корневой `CLAUDE.md` — ≤ 50 строк
3. Для каждого файла сверх лимита:
   * Выдели части, которые **не нужны каждой сессии** (история, обоснования, альтернативы, детали редкого использования).
   * Предложи пользователю: что вынести в `Architecture Decisions` (как ADR), что в `Ideas & Principles`, что в `Conventions`, что просто удалить как неактуальное.
   * Покажи предполагаемый размер после рефактора.
4. По подтверждению построчно / "все" / "никакие":
   * Убери блок из shared-файла.
   * Добавь соответствующую запись в Linear Doc через MCP.
   * При необходимости оставь в shared короткую ссылку на Linear.
5. В конце — напиши саммари аудита в Session Log одной записью (что было, что вынесено, итоговые размеры).

## Ориентиры при ревизии

* Устоявшееся решение в shared → кандидат в ADR (перенос в Architecture Decisions)
* "Почему мы так делаем" → кандидат в Ideas & Principles
* Историческая деталь, которая уже не актуальна → удалить
* Формат-шаблон / пример для будущего → оставить, но коротко

## Когда запускать

* Раз в ~квартал — плановый аудит
* Триггерно — когда кто-то видит что файл перевалил за лимит

## Чего НЕ делать

* Не удалять информацию, которая не переехала в Linear. Сначала перенос — потом удаление.
* Не менять формат и тон файлов без обсуждения с пользователем.
* Не дублировать одну и ту же запись в несколько Linear Docs.
