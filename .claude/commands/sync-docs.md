# /sync-docs

Форсированная синхронизация содержательного изменения из текущей сессии Leaf в публичный whitepaper `gundemtech/leaf-docs`.

## Аргументы
`$ARGUMENTS` — короткое описание того, что надо засинкать. Если пусто — возьми последнее принятое решение из текущего диалога.

## Алгоритм

1. **Определи тему** изменения из `$ARGUMENTS` или последнего обмена в сессии.
2. **Найди целевой файл** в `~/Desktop/Leaf/leaf-docs/docs/`:
   - архитектура / storage / MCP / share controls / presence → `03-architecture/`
   - ICP / сигналы / MVP / pricing → `02-product/`
   - философия / won't-list / видение → `01-vision/`
   - конкуренты / дифференциатор → `04-market/`
   - глоссарий / open tensions / changelog → `05-reference/`
3. **Прочитай целевой файл**, пойми как лучше встроить изменение.
4. **Обнови markdown**:
   - основной текст — как будто это теперь канон,
   - сверху (или в нужном месте) добавить admonition:
     ```markdown
     !!! note "Изменение vX.Y — YYYY-MM-DD"
         Раньше: <кратко>. Теперь: <кратко>. Причина: <1 строка>.
     ```
   - версию бери из `leaf-docs/CLAUDE.md` (текущая + 1, если ещё не бампали в этой волне правок).
5. **Допиши `docs/05-reference/changelog.md`** — одна строка вида `- vX.Y (YYYY-MM-DD) — <тема>: <что поменялось>`.
6. **Commit + push**:
   ```bash
   cd ~/Desktop/Leaf/leaf-docs
   git add -A
   git commit -m "docs: <понятное сообщение>"
   git push origin main
   ```
   Если push просит credentials — сообщи юзеру и остановись на коммите.
7. **Отчитайся**: файл(ы), коммит hash, ссылка на автодеплой `https://leaf-docs.gundem.tech`.

## Guardrails
- Не синкать ephemeral-обсуждения без принятого решения.
- Не трогать `mkdocs.yml` / `nav` без явного запроса (чтобы не ломать структуру навигации).
- Если несколько разделов затронуто — один коммит на всё изменение, не дроби.
- Если репо `~/Desktop/Leaf/leaf-docs` не найден — сообщи юзеру и попроси склонировать.
