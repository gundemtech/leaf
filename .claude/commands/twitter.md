# /twitter

Сгенерируй пост для Twitter / X о том, что мы только что сделали — обычно вызывается сразу после успешного коммита/пуша новой фичи в той же Claude Code сессии.

## Аргументы

`$ARGUMENTS` — опциональный угол / режим:
- (пусто) → **single tweet** ≤ 280 символов. Дефолт.
- содержит `тред` / `thread` / `--thread` → **тред** из 3-5 твитов, каждый ≤ 280.
- любой другой текст без слова «тред» → угол поста (single tweet с уклоном в указанную сторону).
- комбинация: `тред, сравни с гугловским` → тред + угол.

## Источники фактов

В порядке приоритета:

1. **Текущая Claude Code сессия.** Что коммитили, какие файлы трогали, какой spec/plan читали. Первичный источник.
2. **`.claude/shared/current-state.md`** — последний снэпшот. Для:
   - правильного имени фичи,
   - контекста «в рамках чего» (Phase, Layer A/B),
   - не врать про не-сделанное.
3. **`.claude/shared/glossary.md`** — для имён фич / MCP tools.
4. **`$ARGUMENTS`** — модулирует угол, не подменяет факты.

**Не выдумывай.** Если факта нет в сессии и в `current-state.md` — спрашивай.

## Стиль

База — тот же стандарт, что и в `/linkedin`, образец — пост Димы про Vox. Что обязательно:

- **NO DASHES. ВООБЩЕ.** Жёсткое правило, нарушать нельзя. Запрещены: `—` (em-dash), `–` (en-dash), `-` (hyphen-minus) в любых позициях: вставные конструкции, составные слова, диапазоны. Образец Димы про Vox содержит тире — **это образец стиля, а НЕ примера пунктуации**. Замены:
  - `Leaf — ambient memory layer for Mac` → `Leaf, ambient memory layer for Mac,` или отдельным предложением: `Leaf is the ambient memory layer for Mac.`
  - `Counts hide bugs — latencies expose them` → двоеточие или точка: `Counts hide bugs. Latencies expose them.`
  - `5-min polling` → `5 min polling`. `natural-language queries` → `natural language queries`. `Mac-only` → `Mac only`. `open-source` → `open source`.
  - Underscores в коде (`get_github_activity`): не тире, разрешены.
  - **Перед выдачей: прогон по `—`, `–`, `-`. Ни одного быть не должно.** На Twitter особенно: единственное тире сразу выглядит как «текст из LLM», стиль теряется.
- **LA startup vibe, не press release.** Тон как у фаундера ранней стадии в личном тви, не как у корпоративного аккаунта.
  - **«You», не «developers».** Прямой адрес читателю.
  - **Разговорная плотность:** «just dropped», «here's the move», «spoiler:», «real talk» в меру. На single tweet даже одно такое слово ставит тон.
  - **Меньше «We shipped», больше «Just dropped».**
  - **ЗАПРЕЩЕНО:** tech-bro speak. «Absolutely insane», «this is huge», «let's go», «stoked», «massive W», «cooked», «based» — это та же корпоративная вода, в маске. Образец Димы про Vox молодой и прямой, но в нём ноль tech-bro-фраз. Целимся туда.
- **Hook = продающий, через боль или резонанс с читателем.** Первый твит решает, читают ли остальное (в треде) или ставят like (на single). Слабо: «Most dev dashboards count actions» (факт). Сильно:
  - «You shipped four PRs this week. Did it feel like four?» (резонанс с самочувствием)
  - «Stop guessing if Monday was slower than Friday.» (боль)
  - «Counting work is easy. Knowing how it went is the hard part.» (парадокс)
  
  После hook'а можно противопоставить категорию («Most dev dashboards count. Leaf measures rhythm.») — это второй слой, не первый.
- **Поменьше технической инфы.** На Twitter правило ещё жёстче чем на LinkedIn: 280 символов не место для дампа. Конкретно:
  - **Цифр 1 максимум за single tweet, 1-2 за тред.** Хорошо: «average cycle 11 hours» (одна резонирующая). **Плохо (никогда):** `PRs merged: 4 · avg cycle 11h, Reviews: 6 · avg wait 2h, Closed: 3 · avg duration 1d 4h` — это дамп интерфейса, читать невозможно, читателю фуфу. Если хочешь дать число, дай одно следствие в человеческой форме: «Most PRs merge in under a day. One sat for three.»
  - **Не описывай UI / popover / API / JSON.** «Hover the menu bar», «structured JSON», «MCP-capable AI client» — это техническая инструкция, не пост. Один намёк: «Ask Claude how long your last PR sat for review» уже достаточно.
  - **Не лезь в кишки в треде.** Bug story в твите 3-4 допускается, но **только про человеческий момент** («turns out we'd been silently dropping half the data»), не про архитектуру (`PullRequestEvent action: merged vs closed plus merged: true`).
  - **Тест:** твой друг-не-разработчик понял бы первый твит? Если на 5-м слове он спотыкается о термин, переписывай.
- **Короткие предложения.** Лучше 6-8 слов, чем 15.
- **Конкретика, не маркетинг.** «5 min polling», «one keystroke away», «1.7 MB delta»: да. «Революционный», «бесшовный»: нет.
- **Никаких эмодзи. Никаких хэштегов.** Совсем. Это сознательный стиль, не упущение.
- **Без «I'm excited to share…»**, «proud to announce», «stay tuned», «what do you think?», «DM me». Сразу к делу.
- **Имя продукта:** **Leaf**, без вариаций. Если хочется сказать что это, отдельным предложением: `Leaf is the ambient memory layer for Mac.` Не через тире.
- **Язык:** английский.
- **Термины из whitepaper переводи на внешний язык.** «Layer A/B/C», «Phase X.Y», «Section A/B», «derived insights», `signal_type`: внутренний словарь, читателю Twitter он ничего не значит. На single tweet особенно вредно: каждый внутренний термин съедает символы и теряет читателя. Имена **MCP tools** (`get_github_activity` и т.п.): один раз за тред максимум, на single tweet чаще всего лучше без них.

## Режим: single tweet

- **Лимит:** строго ≤ 280 символов (включая пробелы, переносы строк, ссылки). Считай руками — Twitter режет точно.
- **Структура:** 1-3 коротких предложения. Часто работает «before X / now Y» в две строки + одна фраза-вывод.
- **Без ссылок** в основном dispatch'е. Ссылку юзер сам добавит к posту перед публикацией если надо.
- **Цель:** одна мысль, доведённая до точки. Не «вот что мы сделали + почему + кому это надо» — это будет каша. Только «вот что и почему важно».

Пример формы (для понимания плотности, не для копирования):

> Most translators wait until you're done typing. Vox doesn't. Type, and the translation streams as you pause. A good tool disappears.

Это 196 символов, 4 предложения, before/after, финал-афоризм. То же плечо для нашего твита.

## Режим: тред

Активируется если в `$ARGUMENTS` есть `тред` / `thread` / `--thread`.

- **Длина:** 3-5 твитов. Меньше 3 — это не тред, делай single. Больше 5 — никто не дочитает.
- **Каждый твит ≤ 280 символов.** Считай каждый отдельно.
- **Output:** твиты разделены строкой `---` на отдельной строке. Без нумерации (`1/5` и т.п.) — Twitter сейчас сам показывает позицию в треде, нумерация съедает символы.
- **Структура треда:**
  - **Tweet 1** — hook. Одно предложение «вот что мы сделали и почему это интересно», обязательно цепляющее. Если первый твит слабый, тред не читают.
  - **Tweet 2-3** — конкретика. Что было раньше / что теперь / какая числовая характеристика. Здесь живёт before/after.
  - **Tweet 4** (если есть) — нюанс или техническая деталь, которая показывает что мы знаем что делаем.
  - **Последний твит** — вывод одной фразой. Принцип, а не «follow for more».

## Output

Только текст поста. Никаких:
- префиксов («Here's the tweet:»),
- комментариев про длину или выбор формата,
- markdown,
- эмодзи / хэштегов,
- ссылок (юзер добавит сам если надо).

Single tweet — одним блоком. Тред — твиты, разделённые `---` на отдельной строке.

## Sanity check перед выдачей

1. **NO DASHES?** Прогон поиском по `—`, `–`, `-`. Ни одного быть не должно ни в одном твите. Это первая проверка — на Twitter одно тире сразу видно как LLM-стиль.
2. **Считал символы каждого твита?** Single ≤ 280, каждый твит в треде ≤ 280. Twitter режет посимвольно.
3. **Факты из сессии / current-state.md?** Цифры реальные, не выдумал.
4. **Hook продающий, не констатация?** Первый твит должен резонировать с читателем («You shipped four PRs this week. Did it feel like four?», «Stop guessing if Monday was slower than Friday.»), не просто констатировать факт. Категорийное противопоставление — второй слой, не первый.
5. **LA startup vibe, не press release / не tech-bro?** Прогон по «excited», «thrilled», «proud», «revolutionary», «seamless» (press release): выкидывай. Прогон по «absolutely insane», «massive W», «let's go», «stoked», «cooked» (tech-bro): тоже выкидывай. Между ними «just dropped», «real talk», «spoiler» — в меру.
6. **Поменьше технической инфы.** Цифр 1 за single tweet (1-2 за тред). Не описывай UI / JSON / API. Bug story только если про человеческий момент. Тест: друг-не-разработчик понял бы первый твит?
7. **Внутренние термины переведены?** Прогон по «Layer A/B/C», «Phase X.Y», «Section A/B», «derived insights», `signal_type`: если в твите, замени. MCP tool names: один раз за тред максимум, на single tweet чаще без них.
8. **Single mode проверен на одну мысль?** Если в твите две идеи: режь на одну, иначе каша.

Если что-то не сходится — переписывай молча, выдай финальную версию.

## Когда не запускать

- В сессии не было содержательного коммита и `$ARGUMENTS` пустой — нет фактов для поста.
- Юзер просит твит про то, чего ты не видел в сессии и в `current-state.md` нет — не фантазируй, попроси факты.
