## 1. Scope

Pure UI surface wire-up: route `DerivedInsights.inboxItems(filter:query:)` substrate (shipped Phase 8.1) through `InsightsSnapshot` and `InsightsReader.refresh()` into the existing `InboxBlock` placeholder shell (created Phase 8.2). Master spec §4.4 layout — `LeafInput` search field + filter chip row (All / Reviews / Questions / Mentions) + scrollable item list (max-height 320pt) + severity dot leading edge + aggregation count inline suffix + tap-to-open external URL + empty state.

**Substrate landed in Phase 8.1, no changes:**

- `DerivedInsights.inboxItems(filter:query:) throws -> [InboxItem]` (defaults `.all` / `""`). Empty by default (stub returns `[]` until Phase 4.8/4.9 wire Layer B sources; live for open questions + blockers via D3 detection tables).
- `InboxItem { id, kind, severity, title, sourceMeta, sourceURL?, aggregatedCount, createdAtMs }`.
- `InboxKind { reviewRequest, commentOnMyWork, mention, openQuestion, blocker }`.
- `InboxSeverity { danger, warn, muted }` with `sortRank` 0/1/2 — substrate already sorts severity asc → `createdAtMs` desc.
- `InboxFilter { all, reviews, questions, mentions }` with `admits(_:)` — `.reviews`=`reviewRequest`, `.questions`=`openQuestion`, `.mentions`=`mention`. `commentOnMyWork` + `blocker` only appear in `.all`; design respects this.
- `ProdInsights+InboxItems.swift` — 14-day age cutoff, 60-char `body_excerpt` truncation at SQL boundary, in-Swift aggregation by `(kind, sourceURL)` (currently inert because `sourceURL` is nil for D3-derived items; activates when Layer B wires GitHub/Linear URLs Phase 4.8/4.9).

**Hard exclusions (out of scope):**

- ❌ Substrate enrichment of `sourceURL` for Layer B (Phase 4.8 Linear / Phase 4.9 GitHub).
- ❌ Per-keystroke SQL re-fetch (P6 uses single `.all` / `""` fetch + view-side in-memory filter; see §6 OQ-C rationale).
- ❌ Search debounce strategy beyond view-side `@State`. Re-evaluate when cardinality > 1000 items (carry C-15).
- ❌ Background re-fetch when filter chip changes (snapshot is immutable per refresh; chip just re-filters in memory).
- ❌ WHERE STOPPED wire-up (P7).
- ❌ Analytics tab rename (P8) / polish + a11y sweep (P9).
- ❌ Click-through routing past `NSWorkspace.shared.open(sourceURL)` — no in-app push, no `RouteCoordinator.openURL(_:)` extraction (deferred to Track-9 if other blocks need it; carry C-16).

## 2. Architecture

Substrate already complete. P6 adds three thin layers + two new view files:

1. **`InsightsSnapshot.inboxItems`** — new field, defaulted `[]` in both inits (mirror P3 `todayMetrics` / P4 `youNowState` / P5 `sameTaskTeammates`).
2. **`InsightsReader.refresh()`** — 18th sequential `try insights.inboxItems(filter: .all, query: "")` call between `sameTaskTeammates` fetch and `InsightsSnapshot` construction.
3. **`InboxBlock(items: [InboxItem])` body rewrite** — placeholder `LeafEmptyState` → `LeafInput` search + filter chip row + scrollable item list + 3-state branch (empty-data / no-filter-match / populated).
4. **`InboxItemRow` (new file)** — single-item view; severity dot + title-with-count-suffix + sourceMeta line + tap-to-open.
5. **`InboxFilterRow` (new file)** — 4 filter pills bound to `@Binding<InboxFilter>` via `LeafPill` wrapped in `Button`.

`HomeContent` in `HomeView.swift` adjusts one call-site: `InboxBlock()` → `InboxBlock(items: snapshot.inboxItems)`.

## 3. UI specification

### 3.1 Block layout

```swift
VStack(alignment: .leading, spacing: LeafSpace.md) {
  Text("INBOX").leafSectionLabel().foregroundStyle(LeafColor.text.tertiary)

  LeafCard(padding: .regular) {
    VStack(alignment: .leading, spacing: LeafSpace.sm) {
      LeafInput(text: $searchQuery, placeholder: "Search inbox…",
                prefixIcon: .system("magnifyingglass"))
      InboxFilterRow(selected: $selectedFilter)
      LeafDivider()
      if items.isEmpty {
        <empty-data state>           // substrate returned []
      } else if filteredItems.isEmpty {
        <no-match state>             // filter or search hides everything
      } else {
        ScrollView {
          LazyVStack(alignment: .leading, spacing: LeafSpace.xs) {
            ForEach(filteredItems) { item in
              InboxItemRow(item: item)
            }
          }
        }
        .frame(maxHeight: 320)
      }
    }
  }
}
.animation(.easeInOut(duration: 0.25), value: filteredItems)
```

No tone-border overlay (heterogeneous item kinds; the section itself carries no state color).

### 3.2 Filtered items (view-side, in-memory)

```swift
private var filteredItems: [InboxItem] {
    let trimmed = searchQuery.trimmingCharacters(in: .whitespacesAndNewlines).lowercased()
    return items.filter { item in
        guard selectedFilter.admits(item.kind) else { return false }
        guard !trimmed.isEmpty else { return true }
        return item.title.lowercased().contains(trimmed)
            || item.sourceMeta.lowercased().contains(trimmed)
    }
}
```

Substrate already sorts by `severity.sortRank` asc → `createdAtMs` desc. View preserves substrate order; no re-sort.

### 3.3 Item row (`InboxItemRow.swift`)

```swift
struct InboxItemRow: View {
    let item: InboxItem

    var body: some View {
        Button(action: handleTap) {
            HStack(alignment: .top, spacing: LeafSpace.sm) {
                LeafDot(tone: dotTone, size: .md)
                    .padding(.top, LeafSpace.xs)
                    .accessibilityHidden(true)

                VStack(alignment: .leading, spacing: LeafSpace.xxs) {
                    titleLine
                    Text(item.sourceMeta)
                        .font(LeafType.body.small)
                        .foregroundStyle(LeafColor.text.tertiary)
                        .lineLimit(1)
                }

                Spacer(minLength: 0)
            }
            .contentShape(Rectangle())
        }
        .buttonStyle(.plain)
        .disabled(item.sourceURL == nil)
        .accessibilityLabel(a11yLabel)
        .accessibilityAddTraits(item.sourceURL == nil ? [] : .isButton)
    }

    private var titleLine: some View {
        HStack(spacing: LeafSpace.xxs) {
            Text(item.title)
                .font(LeafType.title.small)
                .foregroundStyle(LeafColor.text.primary)
                .lineLimit(2)
            if item.aggregatedCount > 1 {
                Text("(\(item.aggregatedCount))")
                    .font(LeafType.body.small)
                    .foregroundStyle(LeafColor.text.tertiary)
            }
        }
    }

    private var dotTone: LeafDotTone {
        switch item.severity {
        case .danger: return .danger
        case .warn:   return .warning
        case .muted:  return .muted
        }
    }

    private var a11yLabel: String {
        let suffix = item.aggregatedCount > 1 ? " (\(item.aggregatedCount) similar)" : ""
        let action = item.sourceURL == nil ? "" : ", tap to open"
        return "\(severityWord), \(item.title)\(suffix), \(item.sourceMeta)\(action)"
    }

    private var severityWord: String {
        switch item.severity {
        case .danger: return "Urgent"
        case .warn:   return "Needs response"
        case .muted:  return "Informational"
        }
    }

    private func handleTap() {
        guard let url = item.sourceURL else { return }
        NSWorkspace.shared.open(url)
    }
}
```

### 3.4 Severity → dot tone mapping

| `InboxSeverity` | `LeafDotTone` | Tint |
| --- | --- | --- |
| `.danger` | `.danger` | `LeafColor.status.danger` (red) |
| `.warn` | `.warning` | `LeafColor.status.warning` (amber) |
| `.muted` | `.muted` | `LeafColor.text.tertiary` (grey) |

Master spec §4.4 emoji bullets (🔴/🟡/⚪) realised as `LeafDot(size: .md)` (8pt) for visual consistency with rest of design system. Token-only — no hardcoded color.

### 3.5 Filter chip row (`InboxFilterRow.swift`)

```swift
struct InboxFilterRow: View {
    @Binding var selected: InboxFilter

    private static let chips: [(filter: InboxFilter, label: String)] = [
        (.all, "All"),
        (.reviews, "Reviews"),
        (.questions, "Questions"),
        (.mentions, "Mentions"),
    ]

    var body: some View {
        HStack(spacing: LeafSpace.xs) {
            ForEach(Self.chips, id: \.filter) { chip in
                Button {
                    selected = chip.filter
                } label: {
                    LeafPill(title: chip.label,
                             tone: selected == chip.filter ? .accent : .neutral)
                }
                .buttonStyle(.plain)
                .accessibilityLabel("\(chip.label) filter")
                .accessibilityAddTraits(.isButton)
                .accessibilityHint(selected == chip.filter ? "Selected" : "Tap to filter")
            }
        }
    }
}
```

Tone swap: `.accent` (selected) vs `.neutral` (default). Both tones exist in `LeafPillTokens.Tone` already; no token expansion.

### 3.6 Search field

Reuses existing `LeafInput` with `prefixIcon: .system("magnifyingglass")` and default `size: .md` (36pt height — `.sm` doesn't exist in `LeafInputTokens.Size` enum, only `.md`/`.lg`; `.md` is the default and fits the in-card density). No debounce — pure in-memory filter on `@State searchQuery: String = ""` (≤ 100 items per Discovery §2 14-day cutoff; `String.contains` on ≤200 strings is microseconds).

### 3.7 Empty / no-match states

**Empty-data state** (`items.isEmpty` — substrate returned `[]`, the "All clear" path):

```swift
LeafEmptyState(
    icon: LeafIcons.brand.leaf,
    title: "All clear.",
    description: "No reviews, questions, or mentions right now.",
    ctaTitle: nil,
    onCTA: nil
)
```

No CTA — per master spec §4.4 empty inbox = positive state.

**No-match state** (`!items.isEmpty && filteredItems.isEmpty` — filter/search hides everything):

```swift
LeafEmptyState(
    icon: LeafIcons.brand.leaf,
    title: "No matches.",
    description: "Try a different filter or clear the search.",
    ctaTitle: "Clear filters",
    onCTA: {
        selectedFilter = .all
        searchQuery = ""
    }
)
```

CTA resets both filter + query in one tap.

### 3.8 Max-height scroll

`ScrollView { LazyVStack { ForEach } }.frame(maxHeight: 320)` per master spec §4.4. `LazyVStack` (not `VStack`) — defensive for future cardinality growth past 14-day window if substrate constraint changes. Pure structural; no `id`-based diff cost on ≤100 rows.

### 3.9 Tap target

Whole-row `Button(action: handleTap)` `.buttonStyle(.plain)`. `handleTap`:

```swift
guard let url = item.sourceURL else { return }
NSWorkspace.shared.open(url)
```

`Button` is `.disabled(item.sourceURL == nil)` — items without URL (D3-derived open questions / blockers today) render as inert informational rows. No visual fade — substrate-known limitation, not an error state; visual fade would falsely imply "broken row". A11y trait `.isButton` only added when URL is non-nil.

### 3.10 Aggregation count

Inline suffix after title when `item.aggregatedCount > 1`: `"Anton commented on PR #18 (5)"`. `(5)` rendered in `LeafColor.text.tertiary` to dim against the primary title. Substrate dedups by `(kind, sourceURL)`; view trusts the array as-is (no additional fold).

### 3.11 Animation

`.animation(.easeInOut(duration: 0.25), value: filteredItems)` on the inner content for filter/search transitions. Mirrors P5 row-set animation.

## 4. Data flow

```text
Layer B / D3 detection tables (open_questions, blockers; gh_*, linear_*, slack_* events)
        ↓
ProdInsights.inboxItems(filter: .all, query: "")           ← 14-day window, 60-char body_excerpt cap,
                                                              aggregation by (kind, sourceURL)
        ↓
InsightsReader.refresh() — 18th sequential SQL call between sameTaskTeammates and snapshot init
        ↓
InsightsSnapshot.inboxItems: [InboxItem]                    ← immutable per refresh
        ↓
HomeContent → InboxBlock(items: snapshot.inboxItems)
        ↓ (view-side)
@State selectedFilter, @State searchQuery
        ↓
filteredItems = items.filter { admits(kind) && contains(query) }
        ↓
Rendered scroll list + state branches (empty-data / no-match / populated)
```

Crucial: snapshot fetches **once** per `refresh()` with `.all`/`""`. Filter and search are pure view-side concerns. Re-fetch happens only on next `refresh()` tick (timer / focus change / manual reload — same as other blocks).

## 7. Privacy walkback audit

### 7.1 No new payload surface

`InboxItem` fields broken down:

- `id` — opaque string (UUID or hash of `(kind, sourceURL)`); local-only.
- `kind` — local enum.
- `severity` — local enum.
- `title` — already in payload pre-P6. Substrate caps to safe length. Examples: "Anton requested your review on PR #18" / "Open question on LEAF-204".
- `sourceMeta` — already in payload pre-P6. Examples: "GitHub · 2h ago" / "Slack #engineering · 5m ago".
- `sourceURL` — external URL only (GitHub PR / Linear issue / Slack thread permalink). Not stored, not broadcast — opened via `NSWorkspace.shared.open(_:)` and discarded.
- `aggregatedCount` — derived integer.
- `createdAtMs` — timestamp.

**Body content excluded by substrate**: `body_excerpt` from `open_questions.body` / `blockers.body` is truncated to 60 chars at the SQL boundary inside `ProdInsights+InboxItems.swift` (Discovery §2 lines 134–138), and **only used by substrate** to build `title` (D3 patterns surface a phrasing like "Should we proceed without …?"). The raw body field is never exposed on `InboxItem` directly. The 60-char cap is therefore enforced at parser boundary, well before view layer.

### 7.2 Sentinel-injection test (master spec §7 mandate — first Track-8 sentinel)

Master spec §7 explicitly requires: *"Add LEAKED_SENTINEL_INBOX_BODY sentinel-injection test to RelayBodyLeakageTests before P6 merge."* This is the **first sentinel test in Track-8** (P3/P4/P5 derived metrics / state enums / opaque IDs needed no sentinel coverage).

**Test file:** `Packages/LeafCore/Tests/LeafCorePrivateTests/RelayBodyLeakageTests.swift` — append `testInboxBodyDoesNotLeakIntoPresenceState_INBOX`.

**Pattern** (mirror Track-6 P1 `testEventBodyDoesNotLeakIntoPresenceState_ClaudeCode`):

1. Inject sentinel `"LEAKED_SENTINEL_INBOX_BODY"` into both `open_questions.body` and `blockers.body` of a test SQLCipher fixture (paddings of 80+ chars so the 60-char truncation could leak the sentinel if mishandled).
2. Construct `ProdInsights` against the fixture DB.
3. Call `try insights.inboxItems(filter: .all, query: "")`.
4. For each returned `InboxItem`, assert sentinel does **not** appear in `item.title` or `item.sourceMeta`.
5. Also drive the broadcast surface: simulate a `presence_outgoing` envelope round-trip (or assert via the existing helpers if available) and verify the sentinel does not appear anywhere in the envelope bytes.

**Rationale:** body_excerpt is allow-listed in MCP `RelayItemBody` schema (substrate accepts it) but is a new INBOX surface. Test ensures truncation happens at parser boundary and never leaks via UI snapshot relay.
